HyperText Markup Language — the structure of a webpage

What is HTML?

HTML stands for HyperText Markup Language. It is the language we use to build the structure of a webpage — like the headings, paragraphs, images, and buttons. Think of HTML as the skeleton of a website. CSS is like the skin (it makes things look nice), and JavaScript is like the muscles (it makes things move and work).

Key Insight
HTML is NOT a programming language. It is a markup language. It just tells the browser "put this text here as a heading" or "put this image here." It does not do logic like "if this then that."

HTML Basics — Tags and Elements

Accessibility (a11y)

Interview Tip
"Accessibility" means making your website usable for everyone, even people who cannot see the screen or cannot use a mouse. Almost every senior-level interview asks about this. Remember these words: alt, aria-label, role, and tabindex.
  • alt on an image — describes what the picture shows, so a screen reader can say it out loud
  • aria-label — gives a hidden name to a button or icon so a screen reader knows what it does
  • tabindex — controls the order in which things get selected when a user presses the Tab key
  • Using real semantic tags — this is the easiest and best way to make a page more accessible

🎯 Most Asked HTML Interview Questions

    What is the difference between HTML and HTML5?

    HTML is the old basic version of the language. HTML5 is the newer version that added many useful things like video, audio, semantic tags (<header>, <nav>), local storage, and better form input types — without needing extra plugins like Flash.

    What are semantic tags? Give an example.

    Semantic tags are tags that tell us the meaning of the content inside them, not just how it looks.

    Example: <nav> tells the browser "this is the navigation menu," while a plain <div> tells the browser nothing about what is inside it.
    What is the difference between id and class?

    id is meant to be used only once on a page — it picks one single, unique element. class can be used on many elements at the same time, so you can style a group of elements together.

    Example: Suhani gives id="profile-pic-suhani" to her own photo (only one), but uses class="student-photo" on every student's photo on the page.
    What is the difference between <div> and <span>?

    <div> is a block-level box — it takes the full width and starts on a new line. <span> is an inline box — it only takes as much width as its content and stays in the same line as the text around it.

    What is the purpose of <!DOCTYPE html>?

    It tells the browser which version of HTML rules to use to read the page. Writing <!DOCTYPE html> tells the browser "please read this as HTML5," so it does not go into an old, buggy mode.

    What is the difference between GET and POST in a form?

    GET sends form data in the URL itself (visible, and has a size limit). POST sends data hidden inside the request body (not visible in the URL, and can carry much more data). We use POST for things like passwords or login forms.

    What are void elements (self-closing tags)? Give examples.

    Void elements are tags that do not need a closing tag because they cannot hold any content inside them.

    Examples: <img>, <br>, <hr>, <input>, <meta>
    What is the difference between local storage, session storage, and cookies?

    Local storage stays saved even after the browser is closed. Session storage clears as soon as the tab is closed. Cookies are small and are sent to the server with every request, while local/session storage stay only in the browser and are not sent automatically.

    What are data attributes in HTML5?

    Data attributes let us store our own custom information directly on an HTML tag, using data-something="value". JavaScript can read this value easily.

    Example: <li data-user-id="12">Vikas</li> — JavaScript can read data-user-id to know which user this list item belongs to.
    What is the difference between async and defer on a <script> tag?

    async downloads the script in the background and runs it the moment it is ready — this may happen before the page has finished loading. defer also downloads in the background, but waits to run the script until the whole page (DOM) has finished loading. Most of the time, defer is the safer choice.

    How do you make a webpage accessible?

    Use semantic tags, add alt text to all images, make sure every button/link can be reached using the Tab key, use aria-label on icon-only buttons, and make sure text has enough color contrast against the background.

    What is the srcset attribute used for in images?

    srcset lets us give the browser several versions of the same image at different sizes. The browser then picks the best one to load depending on the user's screen size, so mobile users don't download a huge desktop-sized image.

    What is the difference between <strong> and <b>?

    Both make text look bold, but <strong> also tells the browser/screen reader "this text is important," while <b> is just visual styling with no extra meaning.

    What are meta tags and why are they important?

    Meta tags go inside <head> and give extra information about the page, like its description for Google search results, or settings for how it should look on mobile phones (viewport).

    What is the difference between block-level and inline elements?

    Block-level elements (like <p>, <div>) take the full width available and always start on a new line. Inline elements (like <span>, <a>) only take the width they need and sit inside the same line as other text.

    What is the difference between <link> and <a>?

    <link> is used inside <head> to connect outside files, like a CSS file. <a> is a clickable link that takes the user to another page or section, and is used inside <body>.

    What is the difference between <script> placed in the head versus at the bottom of the body?

    If a script is placed in the <head> without defer or async, it blocks the page from loading until the script finishes downloading and running. Placing the script at the bottom of <body> (or using defer) lets the page show its content first, which feels faster to the user.

    What is the difference between an absolute path and a relative path in HTML?

    An absolute path is the full address, like https://example.com/images/photo.jpg. A relative path is a short address based on where the current file is, like images/photo.jpg, which points to a folder next to the current page.

    What is the purpose of the lang attribute on the <html> tag?

    It tells the browser and screen readers which human language the page is written in, like English or Hindi. This helps screen readers pronounce words correctly and helps search engines show the page to the right audience.

    What is the difference between <ol> and <ul>?

    <ol> is an ordered list — it shows numbers (1, 2, 3). <ul> is an unordered list — it shows bullet points instead of numbers. Use <ol> when the order matters, like steps in a recipe.

    What does the required attribute do on an input field?

    It tells the browser that this field cannot be left empty. If the user tries to submit the form without filling it, the browser will stop the form and show a small warning message.

    What is the difference between placeholder and value on an input field?

    placeholder shows light grey hint text that disappears the moment the user starts typing. value sets the actual real text that is already filled inside the box, and it will be submitted with the form if not changed.

    What is the difference between an HTML entity and a normal character?

    Some characters like < or > have a special meaning in HTML, so we cannot type them directly in text without confusing the browser. We use entities instead, like &lt; for <, so the browser shows the symbol instead of reading it as a tag.

    What is the difference between iframe and a normal link?

    A normal link (<a>) takes the user away to a different page. An <iframe> embeds another whole webpage inside the current page, like showing a YouTube video or a Google Map directly inside your own site.

    What is the difference between HTML attributes and HTML properties?

    An attribute is what you write in the HTML code, like value="Vikas". A property is the live value JavaScript sees right now, which can change as the user types — even though the original HTML attribute stays the same.

    What is the difference between <script src="..."> and writing JavaScript directly inside <script> tags?

    src="..." tells the browser to load the JavaScript from a separate file. Writing code directly inside the <script></script> tags puts the JavaScript right there in the HTML file itself. Using separate files is better for bigger projects because the code can be reused and cached by the browser.

    What is the use of the title attribute (different from the page title)?

    The title attribute can be added to almost any tag and shows a small tooltip when the mouse hovers over it.

    Example: <abbr title="HyperText Markup Language">HTML</abbr> shows the full meaning when Suhani hovers over the short word "HTML".
    How do you embed a video in HTML5 without using Flash?

    We use the <video> tag, which is built into HTML5 and does not need any plugin.

    <video src="movie.mp4" controls></video>
    What is the difference between defer and putting the script tag right before </body>?

    Both let the page's HTML load first. But defer still downloads the script early (in parallel with the page), while a script placed at the bottom only starts downloading once the browser reaches that line. defer is usually a little faster.

    What is a favicon?

    A favicon is the small icon shown in the browser tab next to the page title. We add it using <link rel="icon" href="..."> inside the head.

    What is the difference between <header> and <head>?

    They sound similar but are completely different. <head> holds page information that is not shown on screen, like the title and meta tags. <header> is a visible part of the page, usually showing a logo or top navigation.

    What does the alt attribute do if the image fails to load?

    If the image cannot load (broken link, slow internet), the browser shows the alt text instead, so the user still knows what was supposed to be there.

    What is the difference between <b>/<i> and CSS font-weight/font-style?

    <b> and <i> are HTML tags that change how text looks directly inside the content. Using CSS properties like font-weight: bold keeps the styling separate from the content, which is usually considered cleaner and easier to maintain.

    What is the difference between the name and id attributes on a form input?

    id is used by CSS and JavaScript to find one exact element on the page. name is used when the form is submitted — it becomes the label of that piece of data sent to the server, like name=Vikas.

    What is the use of the <noscript> tag?

    It shows a message only when the user's browser has JavaScript turned off. It's a backup plan, like saying "please turn on JavaScript to use this site."

    What is the difference between disabled and readonly on an input field?

    disabled completely blocks the input — the user cannot click it, and its value is not sent when the form is submitted. readonly lets the user see and select the text, but they cannot edit it, and its value is still sent with the form.

    What are global attributes in HTML?

    Global attributes are attributes that can be used on almost any HTML tag, like id, class, style, title, and data-* attributes.

    What is the difference between contenteditable and a normal text input?

    contenteditable="true" can be added to almost any tag (like a <div>) to make its content directly editable by the user, right in place — it is not a form field and is not automatically sent with a form.

    What is the purpose of the download attribute on an <a> tag?

    It tells the browser to download the linked file instead of opening it in the browser tab.

    <a href="resume.pdf" download>Download my resume</a>
    What is progressive enhancement in web development?

    It means building a webpage so it works with basic HTML first, and then adding CSS and JavaScript as extra layers to improve the experience. Even if JavaScript fails to load, the page should still be usable in a simple form.

    What is the difference between <script> and <script type="module">?

    A normal script runs as plain JavaScript. A module script (type="module") lets you use modern import and export statements to split your JavaScript into separate reusable files.

Pro Tip — async vs defer, in one line
async: downloads in the background, runs as soon as ready (could be before the page finishes).
defer: downloads in the background, runs only after the whole page is ready. Use defer most of the time.

The Box Model

Every single HTML element is really a rectangle box. The box model is the way CSS describes the space around that rectangle.

/* From outside to inside: margin, then border, then padding, then the content */
.box {
  width: 200px;
  padding: 20px;
  border: 2px solid black;
  margin: 10px;
  box-sizing: border-box; /* important: makes width include padding + border */
}
Common Mistake
Always set box-sizing: border-box on everything. Without it, padding and border get added on top of the width you set, which makes boxes bigger than you expected.

Flexbox

Flexbox lines up items in one direction — either a row or a column. It is great for things like a navigation bar or a row of buttons.

🧩 Flexbox Quick Reference
.container {
  display: flex;
  flex-direction: row | column;

  /* lines items up on the main line (left-right if row) */
  justify-content: flex-start | center | space-between;

  /* lines items up on the cross line (up-down if row) */
  align-items: stretch | center | flex-start;

  gap: 16px; /* space between items */
}
Remember JA → Justify is for the main Axis, Align is for the cross Axis

CSS Grid

CSS Grid lines up items in two directions at once — rows AND columns. It works like a spreadsheet, and is great for full page layouts.

.container {
  display: grid;
  grid-template-columns: repeat(3, 1fr); /* 3 equal columns */
  gap: 20px;
}

🎯 Most Asked CSS Interview Questions

    What is the CSS box model?

    It is the way CSS thinks about every element as a box with four layers, from inside to outside: content, padding, border, and margin.

    What is the difference between display: none and visibility: hidden?

    display: none removes the element completely — it takes up no space at all, like it does not exist. visibility: hidden hides the element, but it still takes up its space on the page (you just can't see it).

    What is specificity in CSS?

    It is the set of rules CSS uses to decide which style wins when two rules try to style the same element. Inline styles win over ID selectors, which win over class selectors, which win over plain tag selectors.

    What is the main difference between Flexbox and Grid?

    Flexbox arranges items in one direction at a time (a row or a column). Grid arranges items in rows and columns together, at the same time, which makes it better for full page layouts.

    What is the difference between position: absolute and position: fixed?

    absolute positions the element relative to its closest parent that has a position set (not static). fixed positions it relative to the browser window itself, so it stays in place even when the page is scrolled.

    What are CSS custom properties (CSS variables)?

    They let us store a value once, like a color, and reuse it everywhere with var(--name). If we change the value in one place, it updates everywhere it is used.

    Example: Vikas sets --brand-color: blue; once, then uses color: var(--brand-color); on ten different buttons.
    What is z-index and when does it actually work?

    z-index controls which element sits on top when two elements overlap. It only works on elements that have a position value other than static (like relative, absolute, or fixed).

    How do you center an element both horizontally and vertically?

    The easiest modern way is Flexbox: display: flex; justify-content: center; align-items: center; on the parent box. Grid also has a one-line trick: display: grid; place-items: center;

    What is the difference between em and rem?

    em is based on the font size of the current element (it can stack up confusingly when nested). rem is always based on the root <html> font size, so it stays predictable everywhere on the page.

    What does box-sizing: border-box do?

    It changes how width is calculated. With it on, the width you set already includes the padding and border, so the box does not grow bigger than expected when you add padding.

    What is the difference between a pseudo-class and a pseudo-element?

    A pseudo-class (like :hover) selects an element in a certain state. A pseudo-element (like ::before) lets you create and style a small extra piece of content that isn't really in the HTML.

    What is mobile-first design?

    It means writing your base CSS for small mobile screens first, and then using min-width media queries to add extra styles for bigger screens like tablets and desktops.

    What is the difference between CSS transitions and animations?

    A transition smoothly changes a property between two states (like normal and hover). An animation, using @keyframes, can have many steps and can even repeat or run automatically without needing a user action like hover.

    What is the CSS cascade?

    The cascade is the process browsers use to decide which CSS rule to apply, when more than one rule could apply to the same element. It looks at importance, specificity, and the order the rules were written in.

    What is the difference between margin and padding?

    padding is the space inside the border, between the border and the content. margin is the space outside the border, between this element and the next one.

    What is margin collapsing?

    When two block elements are stacked one above the other, the top and bottom margins between them don't add up — instead, only the bigger one is used. This is called margin collapsing.

    What is the difference between inline, block, and inline-block?

    block takes full width and starts a new line. inline only takes the width it needs and stays in the line. inline-block stays in the line like inline, but you can still set its width and height like a block.

    What is the purpose of !important and why should we avoid it?

    !important forces a rule to win over almost every other rule. It is risky because it breaks the normal specificity order, and it becomes very hard to override later, which often leads to messy CSS.

    How does flex-grow, flex-shrink, and flex-basis work?

    flex-basis sets the starting size of an item. flex-grow says how much extra space it should take if there is space left over. flex-shrink says how much it should shrink if there isn't enough space. These three are often combined using the shortcut flex: 1.

    What is the difference between min-width/max-width and width?

    width sets one fixed size. min-width sets the smallest the element is allowed to shrink to, and max-width sets the biggest it is allowed to grow to — both are great for making layouts flexible.

    What are CSS combinators?

    Combinators are symbols that connect two selectors to describe a relationship, like a space (descendant), > (direct child), + (next sibling), and ~ (any sibling after).

    What is the difference between nth-child and nth-of-type?

    nth-child(n) counts every child element, no matter its tag name. nth-of-type(n) only counts elements of the same tag type as the selector.

    What is a CSS reset, and why do developers use one?

    Different browsers have slightly different default styles (like default margins on a heading). A CSS reset removes these default styles so the page looks the same no matter which browser the user has.

    What is the difference between relative and absolute units in CSS?

    Absolute units like px always stay the same size. Relative units like %, em, and rem change their size depending on something else, like the parent's size or the root font size.

    How do you make an image responsive in CSS?

    Set max-width: 100%; height: auto; on the image. This lets it shrink down on small screens but never grow bigger than its container.

    What is the difference between overflow: hidden, scroll, and auto?

    hidden cuts off any content that doesn't fit and hides it. scroll always shows a scrollbar, even if it's not needed. auto only shows a scrollbar when the content actually overflows.

    What is the difference between a class selector and an attribute selector?

    A class selector (.box) targets the class attribute specifically. An attribute selector ([type="text"]) can target any attribute and any value, giving more flexible matching.

    What does the gap property do in Flexbox and Grid?

    gap adds space between items inside a flex or grid container, without needing to add margin to each item one by one.

    What is the difference between auto margins and justify-content: center for centering?

    margin: 0 auto centers a block element horizontally inside its parent, but only works when the element has a fixed width. justify-content: center is a Flexbox property used on the parent and centers the children without needing fixed widths.

    What is a CSS pre-processor, like Sass?

    A pre-processor is a tool that lets us write CSS with extra features, like variables, nesting, and reusable mixins, and then converts that code into normal CSS that browsers can understand.

    What is the difference between :hover and :focus?

    :hover applies when the mouse is over the element. :focus applies when the element is selected, usually by clicking on it or moving to it using the Tab key. Keyboard-only users rely on :focus, since they cannot hover with a mouse.

    What is the difference between :first-child and :first-of-type?

    :first-child matches an element only if it is the very first child inside its parent, no matter its tag. :first-of-type matches the first element of a specific tag type, even if other tags appear before it.

    What is a CSS sprite?

    A sprite is one single image file that contains many small icons packed together. CSS then uses background-position to show only one icon at a time. This is done to reduce the number of separate image files the browser needs to download.

    What is the difference between rem units and percentage units for font-size?

    rem always relates back to the root font size, so it stays predictable everywhere. Percentage font-size relates to the parent element's font size, so it can keep shrinking or growing unexpectedly as it is nested deeper.

    What is the purpose of object-fit in CSS?

    object-fit controls how an image or video fills its box. cover fills the box and crops extra parts, contain fits the whole image inside without cropping (may leave empty space).

    What is the difference between visibility: hidden and opacity: 0?

    Both make the element invisible, but opacity: 0 still allows clicks on the element (it's just transparent), while visibility: hidden also blocks clicks. Both still take up space, unlike display: none.

    What is the difference between a fluid layout and a fixed layout?

    A fixed layout uses set widths in pixels, so it stays the same size no matter the screen. A fluid layout uses flexible units like percentages, so it grows and shrinks with the screen size.

    What is the difference between grid-template-columns and grid-auto-columns?

    grid-template-columns defines the exact columns you plan for. grid-auto-columns sets the size for any extra columns the grid creates automatically that weren't explicitly defined.

    What does clamp() do in CSS?

    clamp(min, preferred, max) picks a value that flexes with the screen size, but never goes smaller than the minimum or bigger than the maximum. It is often used for responsive font sizes.

    Example: font-size: clamp(1rem, 2vw, 2rem);
    What is the difference between absolute positioning and floating elements?

    float was the old way to make elements sit side by side, mainly used for wrapping text around images. position: absolute takes the element completely out of the normal flow. Modern layouts use Flexbox or Grid instead of float for most layout needs.

🎯 Most Asked JavaScript Interview Questions

    What is the difference between == and ===?

    == compares two values but first tries to convert them to the same type if they are different. === compares both the value and the type, without any conversion. It is safer to always use ===.

    Example: "5" == 5 is true, but "5" === 5 is false.
    What is a closure? Give a simple example.

    A closure is when an inner function keeps access to the variables of its outer function, even after the outer function has already finished running.

    Example: Vikas writes a function makeGreeting(name) that returns another function. Even after makeGreeting has finished, the returned function still remembers the name it was given.
    What is hoisting in JavaScript?

    Hoisting means JavaScript moves variable and function declarations to the top of their scope before the code actually runs. So you can sometimes use a function before the line where it is written, but a var variable will just be undefined until its line runs.

    What is the difference between null and undefined?

    undefined means a variable has been created but has not been given any value yet. null means a variable has been deliberately set to "nothing" by the programmer.

    What is the event loop?

    JavaScript can only do one thing at a time, but it can still feel fast for things like timers and network calls. The event loop is the system that lets JavaScript run normal code first, and only run things like setTimeout callbacks or fetch results once the main code has finished.

    What is event bubbling?

    When you click on an element, the click event doesn't just fire on that element — it also "bubbles up" and fires on every parent element, all the way up to the document.

    What is event delegation, and why is it useful?

    Instead of adding a click listener to every single button on a page, we add one listener to their shared parent, and use event.target to find out which child was actually clicked. This uses less memory and also automatically works for items added later.

    What is debouncing? Give an example.

    Debouncing makes a function wait until the user has stopped doing an action for a short time, before it finally runs.

    Example: Suhani types in a search box. Instead of calling the API on every single key press, debouncing waits until she stops typing for half a second, then calls the API just once.
    What is throttling? How is it different from debouncing?

    Throttling makes a function run at most once every fixed amount of time, no matter how many times it is triggered. Debouncing waits for a pause before running once. Throttling is used for things like scroll events, where you want regular updates, not just one final update.

    What is prototypal inheritance?

    In JavaScript, objects can inherit properties and methods from another object, called its prototype. If a property is not found on the object itself, JavaScript looks for it on the prototype, then the prototype's prototype, and so on.

    What is a Promise in JavaScript?

    A Promise represents a value that is not ready yet, but will be ready in the future — like the result of a network call. It can be in one of three states: pending, fulfilled (success), or rejected (failure).

    What is async/await?

    async/await is an easier way to write code that uses Promises. It lets us write asynchronous code that looks like normal, step-by-step code, instead of chaining many .then() calls.

    How does this behave differently in a regular function versus an arrow function?

    In a regular function, this depends on how the function was called. In an arrow function, this is "lexical" — it simply takes the value of this from the surrounding code where the arrow function was written.

    What do call, apply, and bind do?

    All three let you control what this means inside a function. call runs the function immediately, passing arguments one by one. apply runs it immediately too, but takes arguments as an array. bind does not run the function — it returns a brand new function with this already locked in, to be called later.

    What is the difference between map, filter, and reduce?

    map changes every item and returns a new array of the same length. filter keeps only the items that match a condition, possibly returning a shorter array. reduce combines every item down into one single final value.

    What is a higher-order function?

    A higher-order function is simply a function that either takes another function as an input, or returns a function as its output. map, filter, and setTimeout are common examples.

    What is the difference between a shallow copy and a deep copy?

    A shallow copy copies only the top level of an object — if the object has a nested object inside it, both the original and the copy will still point to the same inner object. A deep copy fully copies every nested level too, so the two are completely separate.

    What does typeof null return, and why?

    It returns "object". This is actually a well-known bug from the very first version of JavaScript, but it was never fixed because too many websites already depended on this exact behavior.

    What is the Temporal Dead Zone (TDZ)?

    It is the short period between the start of a block and the line where a let or const variable is declared. If you try to use the variable during this period, JavaScript throws an error instead of giving undefined.

    What is the difference between synchronous and asynchronous code?

    Synchronous code runs one line at a time, in order, and each line must finish before the next one starts. Asynchronous code allows certain tasks, like network calls, to run in the background while the rest of the program keeps going.

    What is the spread operator, and what is the rest operator?

    The spread operator (...) expands an array or object into individual items, often used to copy or combine arrays. The rest operator also uses ..., but it does the opposite — it gathers many separate arguments into a single array inside a function.

    What is destructuring in JavaScript?

    Destructuring lets us quickly pull out values from an array or object into separate variables, in one short line of code, instead of accessing each one separately.

    Example: const { name, age } = student; instantly creates two variables, name and age, from the student object.
    What is the difference between a function declaration and a function expression?

    A function declaration (function greet(){}) is fully hoisted, so it can be called before it appears in the code. A function expression (const greet = function(){}) is not hoisted the same way — the variable exists, but it has no value until that line runs.

    What is the difference between forEach and map?

    forEach just runs a function for each item in an array and returns nothing. map also runs a function for each item, but it collects the results and returns a brand new array.

    What is currying in JavaScript?

    Currying turns a function that takes many arguments into a chain of functions that each take just one argument.

    Example: instead of add(2, 3), a curried version looks like add(2)(3).
    What is memoization?

    Memoization is a way to make a slow function faster by saving (caching) the result of a calculation. The next time the same input is given, the saved result is returned instantly instead of doing the slow work again.

    What are template literals?

    Template literals let us build strings using backticks (` `) instead of quotes, and easily insert variables inside using ${variableName}, without messy plus signs.

    What is the difference between Object.freeze() and const?

    const only stops you from reassigning the whole variable to something else, but the object's properties can still be changed. Object.freeze() actually locks the object's properties too, so nothing inside it can be changed.

    What is NaN, and how do you correctly check for it?

    NaN means "Not a Number" — it shows up when a math operation fails to produce a real number. We cannot check it with === because NaN === NaN is actually false. We use Number.isNaN(value) instead.

    What is the difference between Array.from() and the spread operator for converting things into arrays?

    Both can turn array-like or iterable things into a real array. Array.from() can also take a second argument, a mapping function, so it can transform each item while creating the array — the spread operator alone cannot do that.

    What is the difference between let and const when used with objects and arrays?

    const stops you from pointing the variable to a totally new object or array. But it does not freeze the contents — you can still change properties inside the object or push new items into the array.

    What is an IIFE (Immediately Invoked Function Expression)?

    An IIFE is a function that runs immediately, right after it is defined, without needing to be called separately. It is often used to create a private scope, so variables inside don't leak into the rest of the program.

    Example: (function() { console.log('Hello, Vikas!'); })();
    What is the difference between Set and an array?

    An array can have repeated (duplicate) values. A Set automatically removes duplicates — every value inside a Set is unique.

    What is the difference between Map and a plain object?

    A Map can use any type of value as a key, including objects, and keeps the order keys were added in. A plain object usually works best with string keys and doesn't guarantee key order in older engines.

    What is the difference between setTimeout and setInterval?

    setTimeout runs a function once, after a given delay. setInterval keeps running that function again and again, every time the delay passes, until it is stopped with clearInterval.

    What is JSON, and what do JSON.stringify and JSON.parse do?

    JSON is a simple text format used to send data between a browser and a server. JSON.stringify() turns a JavaScript object into a JSON text string. JSON.parse() does the opposite, turning a JSON text string back into a real JavaScript object.

    What is the difference between a stack and a queue, in terms of the call stack?

    The JavaScript call stack works like a stack — Last In, First Out (LIFO). The most recently called function finishes first. This is different from a queue, where the first thing added is the first thing handled (First In, First Out).

    What is the difference between Array.includes() and Array.indexOf()?

    includes() simply returns true or false depending on whether the value exists in the array. indexOf() returns the position number of the value, or -1 if it is not found.

    What is strict mode in JavaScript ('use strict')?

    Strict mode turns on a stricter set of rules for JavaScript, catching common mistakes as real errors instead of silently allowing them — for example, it stops you from accidentally creating a global variable by forgetting let or const.

    What is the difference between Promise.all() and Promise.race()?

    Promise.all() waits for every promise in the list to finish, and fails if even one of them fails. Promise.race() only waits for the very first promise to finish (success or failure) and ignores the rest.

    What is optional chaining (?.) used for?

    It safely checks if a value exists before trying to read a deeper property inside it, so the code doesn't crash with an error if something is missing.

    Example: user?.address?.city will simply return undefined instead of crashing, if user or address doesn't exist.
    What is the nullish coalescing operator (??)?

    ?? gives a backup value, but only when the original value is exactly null or undefined — unlike ||, which also replaces other "falsy" values like 0 or an empty string.

    What is the output of console.log(1 + "2") and why?

    It prints "12". When you add a number and a string together using +, JavaScript converts the number into a string first, and then joins (concatenates) the two strings.

    What is the difference between a callback function and a Promise?

    A callback is simply a function passed into another function, to be run later. A Promise is a more structured object that represents a future result, and is generally easier to chain and handle errors with compared to deeply nested callbacks.

Virtual DOM and Reconciliation

🔄 How React updates the screen
  1. State or props change → React builds a new, lightweight copy of the page in memory, called the Virtual DOM
  2. React compares the new Virtual DOM with the old one — this comparing step is called reconciliation
  3. React finds only the small parts that actually changed
  4. Only those small parts get updated on the real page, not the whole page
Why does this matter?
Changing the real page (real DOM) directly is slow. Comparing in memory first and updating only what's needed makes the page feel fast.

    state is data that lives inside a component and can be changed by that component itself. props is data passed into a component from its parent, and the component receiving it cannot change it directly.

    What are hooks, and why were they introduced?

    Hooks are special functions, like useState and useEffect, that let us use state and other React features inside simple functional components. Before hooks, you needed a class component to use state at all.

    How does the dependency array in useEffect work?

    The dependency array tells React when to re-run the effect. An empty array [] means "run only once, after the first render." Listing variables inside, like [userId], means "run again whenever userId changes." Leaving the array out completely means "run after every single render."

    What is the difference between useMemo and useCallback?

    useMemo saves (caches) the result of a calculation, so it doesn't need to be recalculated unless its dependencies change. useCallback does the same thing, but for a function definition itself, so the same function reference is reused instead of being recreated every render.

    What is prop drilling, and how can we avoid it?

    Prop drilling happens when we pass a piece of data through many components that don't actually need it themselves, just so it can reach one component deep down. We can avoid it using the Context API, or a state management tool like Redux.

    What are controlled and uncontrolled components?

    A controlled component's value is fully managed by React state — every keystroke updates the state, and the input shows that state's value. An uncontrolled component lets the browser manage its own value directly, and React only reads the value when needed, often using a ref.

    What is React's reconciliation process?

    Reconciliation is the process React uses to compare the new Virtual DOM with the previous one, figure out exactly what changed, and update only those specific parts in the real page.

    Why does React need a key prop when rendering a list?

    The key helps React tell items in a list apart from each other, so it can correctly track which item moved, changed, or was removed, instead of having to guess.

    What happens if you use the array index as a list's key?

    It can work fine for a static list that never changes order, but if items are added, removed, or reordered, using the index can confuse React and cause wrong items to update, or strange UI bugs. It's better to use a stable, unique ID instead.

    What is lazy loading in React?

    Lazy loading means only loading a component's code when it is actually needed, instead of loading everything at once when the page first opens. This makes the first page load faster.

    What is the difference between class components and functional components?

    Class components are written using JavaScript classes and use lifecycle methods like componentDidMount. Functional components are plain functions and use hooks like useEffect instead. Functional components with hooks are now the modern, preferred style.

    What is the Context API, and when should you use Redux instead?

    The Context API is built directly into React and is good for sharing simple data, like a theme or logged-in user, across many components. Redux is a separate tool that is more useful for bigger apps with complex, frequently-changing state and many different actions to track.

    What is an Error Boundary in React?

    An Error Boundary is a special component that catches JavaScript errors happening inside its child components, and shows a friendly fallback message instead of crashing the whole application.

    What does React.memo do?

    React.memo wraps a component so that it skips re-rendering if its props have not actually changed since the last render, which can improve performance for components that render often.

    What is the difference between useRef and useState?

    useState causes the component to re-render whenever its value changes. useRef keeps a value between renders too, but changing it does NOT cause a re-render — it's often used to directly access a DOM element, like focusing an input box.

    What is the purpose of the cleanup function inside useEffect?

    The function you return from inside useEffect runs right before the component disappears, or right before the effect runs again. It's used to clean up things like timers or event listeners, so they don't keep running after they're no longer needed (this prevents memory leaks).

    What is JSX, and how is it different from HTML?

    JSX looks almost exactly like HTML, but it is actually JavaScript. A tool called Babel converts JSX into normal JavaScript function calls behind the scenes. One key difference: in JSX, we use className instead of class, since class is a reserved word in JavaScript.

    What are React fragments, and why use them?

    A fragment (<>...</>) lets you group multiple elements together and return them from a component, without adding an extra, unnecessary <div> wrapper to the actual page.

    What is the difference between a component re-rendering and the DOM actually updating?

    Re-rendering means React re-runs the component's function to figure out what it should look like now. Updating the DOM only happens for the specific parts that actually changed compared to before — re-rendering doesn't always mean the visible page changes.

    What is the children prop in React?

    children is a special prop that automatically holds whatever content is placed between a component's opening and closing tags, letting you build flexible wrapper components.

    Example: <Card>Hello, Suhani!</Card> — inside the Card component, props.children would be "Hello, Suhani!"
    What is the difference between useEffect and useLayoutEffect?

    useEffect runs after the browser has already painted the screen. useLayoutEffect runs right before the screen is painted, which can be useful when you need to measure or change something in the DOM before the user sees it, but it can also slow things down if overused.

    How do you pass data from a child component back up to its parent?

    The parent passes a function down to the child as a prop. The child then calls that function (often with some data as an argument) whenever it wants to send information back up.

    What is the rule about calling hooks only at the top level?

    Hooks must always be called in the exact same order every single render, so they cannot be placed inside if statements, loops, or nested functions. This rule lets React correctly match each hook call to its saved data between renders.

    What is server-side rendering (SSR) in the context of React?

    SSR means generating the page's HTML on the server first, before sending it to the browser, instead of building everything in the browser using JavaScript. This can make the page appear faster and helps search engines read the content more easily. Next.js is a popular tool used for this.

    What is the difference between a presentational component and a container component?

    A presentational component only cares about how things look (the UI), and gets its data through props. A container component handles the logic — fetching data, managing state — and passes that data down to presentational components.

    What is React Strict Mode?

    React.StrictMode is a wrapper component that helps catch potential problems early during development, like outdated patterns or unsafe code, by intentionally double-running certain functions. It does not affect the production build seen by real users.

    What is the difference between useState with an object versus multiple separate useState calls?

    When you use one state object, updating it replaces the whole object unless you manually spread in the old values, so you must be careful not to accidentally lose other fields. Using several separate useState calls keeps each value independent and a little simpler to update safely.

    What is code splitting in React?

    Code splitting breaks your JavaScript bundle into smaller pieces, which are only downloaded when actually needed, instead of downloading one giant file upfront. This is often done using React.lazy() together with Suspense.

    What is the purpose of the Suspense component?

    Suspense lets you show a fallback (like a loading message) while a lazily-loaded component or some data is still being fetched, instead of showing a blank page.

    What is a Higher-Order Component (HOC)?

    A Higher-Order Component is a function that takes a component as input and returns a brand-new, improved component with extra features added — for example, adding extra props or wrapping it in a loading screen.

    Why shouldn't you mutate (directly change) state in React?

    React decides whether to re-render by comparing the old and new state. If you change the existing state object directly instead of creating a new one, React might not notice anything changed, and your screen will not update correctly.

    What is the difference between onClick={handleClick} and onClick={handleClick()} in JSX?

    onClick={handleClick} passes the function itself, to be called only when clicked. onClick={handleClick()} calls the function immediately while rendering, and passes whatever it returns instead — this is almost always a mistake.

    What is the purpose of PropTypes in React?

    PropTypes lets you describe what type of data each prop should be, like a string or a number. React then warns you in the console during development if the wrong type of data is passed in by mistake.

    What is the difference between a single-page application (SPA) and a traditional multi-page website?

    In a traditional website, every link click loads a brand-new HTML page from the server. In a single-page application, like a typical React app, the page loads once, and JavaScript swaps content in and out without a full page reload, making it feel faster.

    What is a render prop in React?

    A render prop is a prop whose value is a function, which a component calls to decide what to render. It is an older pattern used to share logic between components, now mostly replaced by custom hooks.

    What is the difference between npm start and npm run build in a React project?

    npm start runs the app in development mode, with helpful error messages and live reloading. npm run build creates an optimized, smaller, faster version of the app meant to be uploaded to a real server for actual users.

    What is the difference between local state and global state?

    Local state lives inside one single component and is not visible anywhere else. Global state is shared and accessible across many different components throughout the app, often managed using Context or Redux.

    What is the difference between a default export and a named export in a React file?

    A file can only have one default export, and it can be imported under any name you choose. A file can have many named exports, but they must be imported using their exact original name (or with an alias using the as keyword).

    What does it mean that React is "declarative" rather than "imperative"?

    Declarative means we describe what the UI should look like for a given state, and React figures out how to make the screen match it. Imperative means manually writing every single step to change the screen yourself, like older plain JavaScript DOM code.

🔵 Redux — State Management

Redux is a tool that keeps all the important data (state) for your whole app in one single place, called the store. Any component can read from it, and the only way to change it is by sending an "action."

// A simple Redux Toolkit slice
import { createSlice } from '@reduxjs/toolkit';

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment(state) { state.value += 1; }
  }
});

export const { increment } = counterSlice.actions;
export default counterSlice.reducer;
    What is Redux, and why is it used?

    Redux is a state management tool that stores all of an app's shared data in one central place, called the store, making it easier to manage data that many different components need to use.

    What are the three main parts of Redux?

    The store holds all the data. An action is a plain message describing what happened, like "add to cart." A reducer is a function that takes the current state and an action, and returns the new state.

    What is a reducer function?

    A reducer is a function that takes the current state and an action as input, and returns a brand new state, without changing the original state directly.

    Why must reducers be "pure functions"?

    A pure function always gives the same output for the same input, and never changes anything outside itself. This makes Redux predictable, and lets tools track exactly how and why the state changed over time.

    What is the difference between Redux and the Context API?

    The Context API is built into React and works well for simple shared data. Redux is a separate, more powerful tool with extra features like time-travel debugging and middleware, better suited for big apps with complex state.

    What is an action creator?

    An action creator is simply a function that builds and returns an action object, so you don't have to write the same object shape by hand every time.

    What does the dispatch function do?

    dispatch sends an action to the Redux store, which then runs the reducer to calculate and apply the new state.

    What is middleware in Redux?

    Middleware sits between dispatching an action and it reaching the reducer. It can be used for things like logging actions, or handling asynchronous tasks like API calls (for example, using "redux-thunk").

    What is Redux Toolkit, and why is it recommended over plain Redux?

    Redux Toolkit is the modern, official way to write Redux code. It removes a lot of repetitive boilerplate code, and comes with good defaults already built in, like Immer for safely updating state.

    What is the useSelector hook used for?

    useSelector lets a React component read a specific piece of data straight out of the Redux store.

    What is the useDispatch hook used for?

    useDispatch gives a component access to the dispatch function, so it can send actions to the store.

    What is the single source of truth principle in Redux?

    It means the entire app's state lives in one single store object, instead of being scattered across many separate components, making it easier to track and debug.

    What is the difference between local component state and Redux state?

    Local state (like useState) is only used and known by one component. Redux state is shared and can be accessed by any component in the entire app.

    What is "redux-thunk" used for?

    Thunk is a type of middleware that lets action creators contain asynchronous logic, like waiting for an API response, before finally dispatching the real action with the data.

    What is immutability, and why does Redux care about it?

    Immutability means never directly changing existing data — always creating a new copy with the changes instead. Redux relies on this to detect what has changed, by comparing old and new state references.

    What is the Redux DevTools extension used for?

    It is a browser tool that lets developers see every action dispatched, inspect the state at each step, and even "time travel" backward and forward through past states, which makes debugging much easier.

    What is a "slice" in Redux Toolkit?

    A slice is a single file containing the state, reducers, and actions for one specific feature of the app, like "cart" or "user," keeping related logic organized together.

    How does Redux Toolkit let you "mutate" state directly inside reducers safely?

    Redux Toolkit uses a library called Immer behind the scenes, which lets you write code that looks like direct mutation, but Immer actually creates a safe, new immutable copy for you automatically.

    What is the typical data flow direction in a Redux app?

    Data flows in one direction: a component dispatches an action, the reducer creates new state from it, the store updates, and then any component reading that state re-renders with the new data.

    When should you NOT use Redux in a project?

    If the app is small and simple, with very little shared data between components, Redux can add unnecessary extra complexity. In such cases, plain useState or the Context API is usually enough.

🟢 Next.js

Next.js is a framework built on top of React. It adds useful extra features like file-based routing, and the ability to render pages on the server before sending them to the browser.

// app/about/page.js -> automatically becomes the /about page
export default function AboutPage() {
  return <h1>About Vikas</h1>;
}
    What is Next.js?

    Next.js is a framework built on top of React that adds extra features like file-based page routing, server-side rendering, and easy ways to make websites load faster and rank better in search engines.

    What is file-based routing in Next.js?

    Instead of manually writing routes in code, Next.js automatically turns each file inside the app or pages folder into a real page on the website, based on its file name and folder path.

    What is the difference between Server-Side Rendering (SSR) and Static Site Generation (SSG)?

    SSR builds the page's HTML fresh on the server every time someone visits. SSG builds the page's HTML once, ahead of time, when the site is built, and then reuses that same HTML for every visitor until rebuilt.

    What is the difference between Client-Side Rendering (CSR) and Server-Side Rendering (SSR)?

    In CSR, the browser downloads a mostly empty page and JavaScript builds the content after loading. In SSR, the server already builds the full HTML before sending it, so the user sees content sooner.

    What are Server Components in Next.js?

    Server Components are components that run and render only on the server, never sending their JavaScript code to the browser. This can make pages load faster, since less JavaScript needs to be downloaded.

    What is the purpose of the getStaticProps function (Pages Router)?

    It lets a page fetch its data at build time, before the site goes live, so the page can be generated as static HTML ahead of time.

    What is the purpose of the getServerSideProps function (Pages Router)?

    It fetches data fresh, on the server, every single time a user requests that page, rather than once at build time.

    What is API routes in Next.js?

    API routes let you write small backend functions directly inside your Next.js project, which can handle requests like form submissions, without needing a completely separate backend server.

    How does Next.js's built-in <Image> component help performance?

    It automatically resizes images for different screen sizes, loads them only when needed (lazy loading), and serves modern, smaller image formats, all without extra setup.

    What is the difference between the Pages Router and the App Router in Next.js?

    The Pages Router is the original, older routing system using a pages folder. The App Router is the newer system using an app folder, which supports Server Components and more flexible layouts.

    What is hydration in the context of Next.js or SSR?

    Hydration is the process where React "wakes up" the static HTML sent by the server, attaching event listeners and making it fully interactive in the browser.

    Why is Next.js considered good for SEO?

    Since pages can be rendered into full HTML on the server (instead of an empty page filled in later by JavaScript), search engines can read the actual page content much more easily.

    What is a layout file in the Next.js App Router?

    A layout file defines UI that is shared across multiple pages, like a navbar or footer, so you don't have to repeat that code on every single page.

    What is dynamic routing in Next.js?

    Dynamic routing lets a single file handle many different URLs that share a pattern, using square brackets in the filename, like [id], to capture a changing value.

    Example: a file named app/student/[id]/page.js can handle both /student/vikas and /student/suhani.
    What is the purpose of next.config.js?

    It is a configuration file used to customize how the Next.js project builds and behaves, such as setting up redirects, image domains, or environment variables.

    What is Incremental Static Regeneration (ISR)?

    ISR lets a statically generated page be automatically rebuilt in the background after a set amount of time, so the page stays fresh without needing to rebuild the entire site.

    What is middleware in Next.js?

    Middleware is code that runs before a request reaches a page, often used for things like checking if a user is logged in, and redirecting them if they are not.

    What is the difference between a Server Component and a Client Component in the App Router?

    A Server Component runs only on the server. A Client Component (marked with 'use client' at the top of the file) runs in the browser too, and is needed for things like click handlers and useState.

    How do environment variables work in Next.js?

    Environment variables are stored in a file like .env.local. Variables that start with NEXT_PUBLIC_ can be used in the browser; other variables stay private and are only available on the server.

    What is the benefit of using Next.js over plain Create React App for a new project today?

    Next.js gives built-in routing, server-side rendering, image optimization, and API routes out of the box, while a plain React app needs these features to be added manually with extra libraries.

🟩 Node.js

Node.js lets us run JavaScript outside of the browser — usually on a server. This means we can use the same language (JavaScript) for both the frontend and the backend of a website.

// A very basic Node.js server, with no extra libraries
const http = require('http');

const server = http.createServer((req, res) => {
  res.end('Hello from Vikas server!');
});

server.listen(3000);
    What is Node.js?

    Node.js is a tool that lets us run JavaScript outside of a web browser, usually to build the backend (server) part of a website or app.

    Is Node.js a programming language or a framework?

    Neither — Node.js is a "runtime environment." It is a program that takes the JavaScript language and lets it run on a computer or server, outside the browser.

    Is Node.js single-threaded or multi-threaded?

    Node.js runs your main JavaScript code on a single thread, but it can still handle many tasks at once (like file reading or network calls) using its event loop, which hands off slow work in the background.

    What is the event loop in Node.js?

    The event loop is the system that lets Node.js handle many requests at the same time, even though it has one main thread. It keeps checking if any background tasks (like a database call) have finished, and runs their callback code when ready.

    What is npm?

    npm (Node Package Manager) is a tool that comes with Node.js, used to install and manage other people's pre-written code packages, like Express or Mongoose, so you don't have to write everything from scratch.

    What is the difference between dependencies and devDependencies in package.json?

    dependencies are packages the actual app needs to run, even after it's deployed. devDependencies are packages only needed while developing, like testing tools, and are not required once the app is live.

    What is the difference between require() and import in Node.js?

    require() is the older CommonJS way of bringing in another file or package. import is the newer ES Module syntax. Node.js supports both, but a project usually needs to be configured to pick one style.

    What are streams in Node.js?

    Streams let Node.js handle data piece by piece, instead of loading an entire huge file into memory at once — useful for things like reading large video files efficiently.

    What is the purpose of the fs module?

    The fs (file system) module lets Node.js read, write, update, and delete files directly on the computer or server it is running on.

    What is middleware in the context of a Node.js server?

    Middleware is a function that runs in between a request coming in and the final response being sent, often used to check things like login status, or to log information about the request.

    What is the difference between synchronous and asynchronous methods in Node.js, like readFileSync vs readFile?

    The synchronous version blocks all other code from running until the file is fully read. The asynchronous version lets other code keep running, and calls you back (with a callback or Promise) once the file is ready.

    What is a callback function, in the context of Node.js?

    A callback is a function passed into another function, to be run later once a task (like reading a file) finishes.

    What is "callback hell," and how do we avoid it?

    Callback hell happens when many callbacks are nested deeply inside each other, making the code hard to read. We avoid it by using Promises or async/await instead, which keep the code flatter and easier to follow.

    What is the purpose of environment variables in a Node.js app?

    Environment variables store settings, like database passwords or API keys, outside of the actual code, so secret information is not hard-coded directly into the files.

    What is the difference between a Node.js global object and the browser's window object?

    In Node.js, the global object is called global, while in a browser it is called window. Both hold global variables and functions, but they are not the same object, since Node.js does not run inside a browser.

    What is a module in Node.js?

    A module is simply a separate JavaScript file whose code (variables, functions) can be exported and reused in other files, helping keep a project organized into smaller pieces.

    What is the purpose of the process object?

    The process object gives information about the currently running Node.js program, like its environment variables (process.env) or the arguments it was started with.

    What is clustering in Node.js?

    Clustering lets a Node.js app create multiple copies of itself to use more than one CPU core at once, helping it handle more requests at the same time on a multi-core computer.

    What is the difference between Node.js and a traditional web server like Apache?

    Node.js uses JavaScript and a single-threaded event loop to handle many requests efficiently. Traditional servers like Apache often create a brand-new thread or process for every single request, which can use more memory under heavy load.

    What is REPL in Node.js?

    REPL stands for Read-Eval-Print-Loop. It is an interactive terminal window where you can type small bits of JavaScript and instantly see the result, useful for quick testing.

🟦 Express.js

Express is a small, simple framework built on top of Node.js. It makes it much easier to create web servers and APIs, without writing a lot of repetitive code by hand.

const express = require('express');
const app = express();

app.get('/', (req, res) => {
  res.send('Hello, Suhani!');
});

app.listen(3000, () => console.log('Server is running'));
    What is Express.js?

    Express is a lightweight framework that runs on top of Node.js, used to build web servers and APIs more easily, with simple ways to handle routes and requests.

    What is routing in Express?

    Routing is how an Express app decides what code to run, based on the URL and the HTTP method (GET, POST, and so on) of an incoming request.

    Example: app.get('/students', ...) only runs when someone visits /students using a GET request.
    What is middleware in Express?

    Middleware functions run between the request arriving and the final response being sent. They can check, change, or log the request, and must call next() to pass control along to the next piece of middleware or the route itself.

    What is the purpose of app.use() in Express?

    app.use() registers middleware that runs for every matching request, often used to set up things like JSON parsing or logging across the whole app.

    What is the difference between app.get(), app.post(), app.put(), and app.delete()?

    These match different HTTP methods. get is for reading data, post is for creating new data, put is for fully updating existing data, and delete is for removing data.

    What is the purpose of req.params?

    req.params holds dynamic values taken directly from the URL itself.

    Example: for a route /student/:id, visiting /student/5 makes req.params.id equal to "5".
    What is the difference between req.params, req.query, and req.body?

    req.params comes from the URL path itself. req.query comes from the part of the URL after a question mark, like ?sort=asc. req.body comes from the data sent in the actual request, usually with a POST or PUT request.

    What does express.json() middleware do?

    It reads incoming JSON data sent in a request and automatically converts it into a normal JavaScript object, which is then made available as req.body.

    How do you handle errors in an Express app?

    You can write a special error-handling middleware function with four parameters, (err, req, res, next), placed after all your normal routes, to catch and respond to errors in one central place.

    What is the purpose of the next() function in Express middleware?

    Calling next() tells Express to move on to the next middleware function or route handler in line. If next() is never called, the request gets stuck and never gets a response.

    What is CORS, and why do we need it in an Express app?

    CORS (Cross-Origin Resource Sharing) is a browser security rule that blocks a webpage from calling an API on a different domain, unless that API explicitly allows it. We add CORS middleware on the server to allow our frontend (perhaps on a different domain) to talk to our backend safely.

    What is the purpose of route parameters versus query parameters?

    Route parameters (/student/:id) are used for required, specific pieces of a URL, like an ID. Query parameters (?sort=asc) are used for optional extra settings, like sorting or filtering.

    What is Express Router used for?

    express.Router() lets you group related routes together in a separate file, keeping a large app organized instead of putting every single route in one giant file.

    How do you serve static files, like images or CSS, using Express?

    You use the built-in express.static('foldername') middleware, which automatically serves any file inside that folder directly to the browser.

    What status codes should an Express API return for success and error responses?

    Common ones are 200 for success, 201 for something created successfully, 400 for a bad request from the client, 401/403 for login or permission issues, and 500 for a server-side error.

    What is the difference between res.send(), res.json(), and res.end()?

    res.send() can send text, HTML, or an object, and Express figures out the right format automatically. res.json() always sends the data as JSON, and is clearer when you specifically want JSON. res.end() just closes the response without sending any extra body content.

    How do you set a custom HTTP status code in Express?

    You chain the .status() method before sending the response.

    Example: res.status(404).json({ message: 'Student not found' });
    What is the purpose of express.Router() versus defining routes directly on app?

    Defining routes directly on app works fine for a small project, but as the app grows, express.Router() lets you split routes into separate files (like studentRoutes.js), keeping the project organized and easier to maintain.

    How do you apply middleware to only one specific route instead of the whole app?

    You pass the middleware function as an extra argument directly inside that one route, before the final handler.

    Example: app.get('/profile', checkLogin, (req, res) => {...}); — here checkLogin only runs for the /profile route.
    What is the order of execution for multiple middleware functions in Express?

    Express runs middleware functions in the exact order they are written in the code, from top to bottom. Each one must call next() to pass control to the next one in line.

    What happens if you don't call next() and also don't send a response in a middleware function?

    The request gets stuck forever. The browser or client keeps waiting, since Express has no instruction to either move on or send back a response.

    What is the difference between application-level middleware and route-level middleware in Express?

    Application-level middleware, added with app.use(), runs for every request that matches its path. Route-level middleware is added only to a specific route, so it only runs for that one route.

    How would Vikas validate that a "name" field is not empty before saving a new student in Express?

    Vikas could check req.body.name inside the route handler (or in a separate validation middleware) before saving, and send back a 400 status with an error message if the name is missing or empty, instead of letting bad data reach the database.

    What is the difference between a 4xx and a 5xx HTTP status code?

    A 4xx code means something was wrong with the request itself, sent by the client (like a missing field, or wrong login details). A 5xx code means something went wrong on the server's side, even though the request itself was fine.

    How can you organize a large Express app into folders like routes, controllers, and models?

    Routes files define which URL goes to which function. Controller files hold the actual logic for what that function does (like talking to the database). Model files (often using Mongoose) define the shape of the data. Splitting code this way keeps each file focused on one job.

🔌 REST API

A REST API is simply an agreed set of rules for how a frontend (like React) can ask a backend (like Express) for data, using normal web addresses (URLs) and standard HTTP methods like GET and POST.

// A simple REST API for students, built with Express
app.get('/api/students', (req, res) => {        // READ all students
  res.json(students);
});

app.get('/api/students/:id', (req, res) => {    // READ one student
  const student = students.find(s => s.id === req.params.id);
  res.json(student);

    What does REST stand for, and what is a REST API?

    REST stands for Representational State Transfer. A REST API is a way of building a backend where each piece of data (like a student) has its own URL, and you use standard HTTP methods (GET, POST, PUT, DELETE) to read or change that data.

    What are the main HTTP methods used in a REST API, and what does each one do?

    GET reads data. POST creates new data. PUT fully replaces existing data. PATCH updates only part of existing data. DELETE removes data.

    What is the difference between PUT and PATCH?

    PUT is meant to replace the entire record with new data. PATCH is meant to update only the specific fields you send, leaving the rest of the record untouched.

    What makes an API "RESTful"?

    A RESTful API follows a few simple rules: each resource (like a student) has its own clear URL, it uses standard HTTP methods correctly, and the server does not remember anything about the client between separate requests (this is called being "stateless").

    What does it mean that REST APIs are "stateless"?

    It means the server does not store any memory of previous requests from a client. Every single request must include all the information the server needs to understand and process it, like a login token, every single time.

    What is a resource in REST API terms?

    A resource is any piece of data the API lets you work with, like a student, a product, or an order. Each resource usually gets its own URL, such as /api/students.

    What is the difference between a path parameter and a query parameter in a REST API URL?

    A path parameter is part of the actual URL path, like the 5 in /api/students/5, and usually identifies one specific item. A query parameter comes after a question mark, like /api/students?sort=marks, and is usually used for optional filtering or sorting.

    Why do REST APIs usually return data as JSON?

    JSON is lightweight, easy for both humans and computers to read, and matches JavaScript's own object format closely, making it simple for a frontend like React to use the data right away.

    What status code should a REST API return when a requested item is not found?

    It should return 404 Not Found, along with a clear message, so the client knows the item simply does not exist, rather than something being broken.

    What is API versioning, and why is it used?

    API versioning means labeling different versions of an API, like /api/v1/students and /api/v2/students, so you can improve or change the API over time without suddenly breaking older apps that still rely on the original version.

    What is the difference between a REST API and a normal website?

    A normal website returns full HTML pages meant to be viewed directly in a browser. A REST API returns raw data, usually as JSON, meant to be used by another program, like a React app, which then decides how to display it.

    What is idempotency in the context of REST APIs?

    An idempotent action gives the same end result no matter how many times you repeat it. For example, calling DELETE on the same student's ID twice still ends with that student being deleted — the second call just has nothing left to delete.

    How would Suhani design a REST API endpoint to update only one student's marks?

    Suhani could create a PATCH /api/students/:id route, sending only the updated marks field in the request body, since PATCH is meant for partial updates rather than replacing the whole student record.

    What is pagination in a REST API, and why is it used?

    Pagination splits a large list of results into smaller pages, like 10 items at a time, instead of sending thousands of records in one single response. This is usually controlled with query parameters, like ?page=2&limit=10.

    What is the difference between a REST API and GraphQL, in simple terms?

    A REST API usually has many separate fixed URLs, each returning a fixed shape of data. GraphQL uses a single URL, and lets the frontend ask for exactly the specific fields it needs in one request, which can reduce extra unused data being sent.

    Why is it considered bad practice to use a verb in a REST API URL, like /getStudents?

    In REST design, the HTTP method itself (GET, POST, and so on) already describes the action. The URL should describe only the resource, like /students, so using GET /students is preferred over GET /getStudents.

🔑 JWT (JSON Web Token)

A JWT is a small, signed piece of text that proves who a user is, without the server needing to remember them. After Vikas logs in correctly, the server gives him a JWT. He then sends that same JWT with every future request, like a digital ID card, to prove he is still logged in.

// Creating a JWT after a successful login
const jwt = require('jsonwebtoken');

const token = jwt.sign(
  { id: user._id },     // the data (payload) we want to store inside the token
  process.env.JWT_SECRET, // a secret key, kept private on the server
  { expiresIn: '1d' }  // the token stops working after 1 day
);

// Checking a JWT sent by the user later
const decoded = jwt.verify(token, process.env.JWT_SECRET);
console.log(decoded.id); // we get back the user's id safely
Common Mistake
Never store the JWT secret key directly in your code. Always keep it in an environment variable (like process.env.JWT_SECRET), so it stays private and is not uploaded to GitHub by accident.
    What is a JWT (JSON Web Token)?

    A JWT is a small piece of text that the server gives a user after they log in successfully. It proves who the user is, and the user sends it back with future requests instead of logging in again every single time.

    What are the three parts of a JWT?

    A JWT has three parts, separated by dots: the header (describes the token type), the payload (the actual data, like a user's ID), and the signature (proves the token was not changed or faked).

    Is the data inside a JWT encrypted?

    No — the payload of a JWT is only encoded, not encrypted, which means anyone can read it if they get the token. This is why we should never put secret information, like a password, inside a JWT's payload.

    What does the JWT signature actually protect against?

    The signature does not hide the data, but it stops anyone from changing the data inside the token without being noticed. If even one character is changed, the signature check will fail on the server.

    What is the purpose of the secret key used when creating a JWT?

    The secret key is used to create and check the token's signature. Only a server that knows this exact secret key can create valid tokens, or confirm that a token it receives is genuine and has not been tampered with.

    What happens when a JWT expires?

    Once the token passes its expiresIn time, the server will reject it as invalid, even if the signature is still correct. The user will then need to log in again, or use a refresh token, to get a brand-new JWT.

    What is a refresh token, and how is it different from a normal JWT (access token)?

    An access token (the normal JWT) is short-lived and used for everyday requests. A refresh token usually lasts much longer, and its only job is to be exchanged for a brand-new access token once the old one expires, without forcing the user to log in again.

    Where should a JWT be stored in the browser — cookies or local storage?

    Both have trade-offs. Local storage is easy to use but can be read by any JavaScript on the page, including malicious scripts. An HTTP-only cookie cannot be read by JavaScript at all, which is generally considered safer against certain attacks, though it needs its own protections too.

    How does a client usually send a JWT to the server with a request?

    It is most commonly sent inside the Authorization header, using the format Bearer <token>.

    What is the difference between jwt.sign() and jwt.verify()?

    jwt.sign() creates a brand-new token, usually right after a successful login. jwt.verify() checks an existing token's signature and expiry, and gives back the original data if the token is valid.

    What happens on the server if jwt.verify() is given a tampered or fake token?

    jwt.verify() throws an error, since the signature will not match. The server should catch this error and respond with a 401 Unauthorized status, instead of letting the request continue.

    Why is using JWTs considered "stateless," compared to traditional server sessions?

    With JWTs, the server does not need to store any record of who is logged in — all the needed information is inside the token itself. With traditional sessions, the server must keep a stored record (often in memory or a database) of each logged-in user.

    What is a common security mistake when working with JWTs?

    A common mistake is putting sensitive information, like a plain password, inside the JWT payload — since the payload is readable by anyone who has the token, even though it can't be changed without breaking the signature.

    How would Vikas's Express app check if a request includes a valid JWT, before allowing access to a protected route?

    Vikas would write a middleware function that reads the token from the Authorization header, runs jwt.verify() on it, and either calls next() to let the request continue if the token is valid, or sends back a 401 error if it is missing or invalid.

🔐 Authentication

Authentication answers one simple question: "Who are you?" It is the process of checking if a user really is who they claim to be, usually by checking their email and password when they log in.

// A simple login route - checking who the user is
const bcrypt = require('bcrypt');

app.post('/login', async (req, res) => {
  const user = await User.findOne({ email: req.body.email });
  if (!user) return res.status(401).json({ message: 'Invalid email or password' });

  // compare the typed password with the saved, hashed password
  const isMatch = await bcrypt.compare(req.body.password, user.password);
  if (!isMatch) return res.status(401).json({ message: 'Invalid email or password' });

  // if we reach here, Suhani really is who she says she is
  const token = jwt.sign({ id: user._id }, process.env.JWT_SECRET);
  res.json({ token });
});
    What is authentication?

    Authentication is the process of confirming who a user actually is, usually by checking something like their email and password during login.

    Why should we never store plain text passwords in a database?

    If the database is ever leaked or hacked, plain text passwords would let anyone instantly see and reuse every user's exact password. Storing passwords safely (hashed) protects users even if the database is exposed.

    What is password hashing, and how is it different from encryption?

    Hashing turns a password into a scrambled value that cannot be reversed back into the original password. Encryption, on the other hand, can be reversed (decrypted) if you have the right key. Passwords should be hashed, not just encrypted, since we never need to see the original password again.

    What is bcrypt, and what is it used for?

    Bcrypt is a popular library used to safely hash passwords before saving them, and to later compare a typed-in password against the saved hash, without ever storing the real password anywhere.

    What is "salting" a password, and why is it useful?

    A salt is random extra data added to a password before hashing it. This makes sure that even if two users have the exact same password, their stored hashes will look completely different, making certain types of attacks much harder.

    What is the typical flow of a login system using JWT-based authentication?

    The user sends their email and password. The server checks the password against the saved hash. If correct, the server creates a JWT and sends it back. The user then includes this JWT with every future request to prove they are logged in.

    What is the difference between session-based authentication and token-based (JWT) authentication?

    Session-based authentication stores login information on the server itself, and gives the browser a small ID (often in a cookie) to look it up. Token-based authentication stores all the needed information inside the token itself, so the server does not need to remember anything between requests.

    What is multi-factor authentication (MFA)?

    MFA asks the user to prove who they are using more than one method, like a password plus a one-time code sent to their phone, making it much harder for someone else to log in even if they steal the password.

    What status code should a login API return when the password is wrong?

    It should return 401 Unauthorized, usually with a general message like "Invalid email or password," without specifically saying whether the email or the password was wrong, for better security.

    Why is it considered bad practice to reveal whether it was the email or the password that was wrong during login?

    If the message specifically says "email not found," an attacker could use this to discover which email addresses are actually registered on the system, one by one. A general error message protects user privacy.

    What is OAuth, in simple terms?

    OAuth is a system that lets a user log in to one app using their existing account from another service, like logging into a website using their Google account, without sharing their Google password with that website directly.

    What is "logging out" actually doing, in a JWT-based system?

    Since the server does not store the JWT anywhere, logging out usually just means deleting the token from where the browser stored it (like local storage or a cookie). The token itself is technically still valid until it expires, unless extra steps like a token blocklist are used.

    What is the difference between authentication and just "checking a password" in code?

    Authentication is the whole overall process — checking who someone is, often involving multiple steps and protections. Checking a password is just one single piece of that bigger process.

🛂 Authorization

Authorization answers a different question than authentication: "What are you allowed to do?" A user can be successfully authenticated (logged in), but still not be authorized (allowed) to do certain things, like an ordinary student trying to access an admin-only page.

Remember it simply: Authentication checks WHO you are. Authorization checks WHAT you can do.

  }
  next(); // Vikas is an admin, so let him continue
}

    What is authorization?

    Authorization is the process of checking what a logged-in user is actually allowed to do or see, after we already know who they are.

    What is the difference between authentication and authorization?

    Authentication checks who the user is, usually during login. Authorization checks what that already-confirmed user is allowed to access or do, like whether a normal student can delete other students' records.

    What status code should be returned when a logged-in user tries to access something they are not allowed to?

    403 Forbidden is the correct status code — it tells the client "I know who you are, but you are not allowed to do this," which is different from 401, which means "I don't know who you are at all."

    What is role-based access control (RBAC)?

    RBAC means giving each user a role, like "student" or "admin," and then deciding what they can access based on that role, instead of setting individual permissions for every single user one by one.

    How would you build authorization middleware in Express to only allow admins to delete a student record?

    You would write a middleware function that checks the logged-in user's role (often read from the decoded JWT), and either calls next() if they are an admin, or responds with a 403 error if they are not, placing this middleware before the actual delete route handler.

    Can a user be authenticated but not authorized? Give a simple example.

    Yes. For example, Suhani logs in successfully as a normal student (she is authenticated), but if she tries to open an admin-only settings page, the server should block her (she is not authorized), even though her login itself was valid.

    Where should authorization checks usually be performed — on the frontend, backend, or both?

    Authorization should always be properly checked on the backend, since that is the only place we can truly trust. Frontend checks (like hiding a button) only improve the experience — a user could otherwise bypass frontend-only checks and call the API directly.

    What is the difference between role-based and permission-based authorization?

    Role-based authorization checks a single broad role, like "admin" or "student." Permission-based authorization is more detailed, checking specific individual abilities, like "can-delete-student" or "can-edit-marks," which can be mixed and matched more flexibly.

    How would you protect an entire group of admin routes at once, instead of checking authorization in every single route?

    You could group all admin routes under one Express Router, and apply the authorization-checking middleware once using router.use(requireAdmin), so every route inside that router is automatically protected.

    What data is typically stored inside a JWT to help with authorization checks later?

    Along with the user's ID, the JWT payload often also includes their role, like { id: user._id, role: 'admin' }, so the server can quickly check their role without needing an extra database lookup on every request.

    What is MongoDB?

    MongoDB is a NoSQL database that stores data as flexible documents (similar to JSON objects), instead of fixed tables with rows and columns like SQL databases.

    What is the difference between SQL and NoSQL databases?

    SQL databases store data in strict tables with a fixed structure (columns must match for every row). NoSQL databases like MongoDB allow each piece of data (document) to have a different, flexible structure.

    What is a collection in MongoDB?

    A collection is similar to a table in SQL. It is a group of related documents, like all the "students" documents stored together.

    What is a document in MongoDB?

    A document is one single record of data, stored in a JSON-like format, like one student's name and marks. A collection is simply a group of many documents.

    What is the _id field in MongoDB?

    Every document automatically gets a unique _id field when it is created, which MongoDB uses to identify that exact document.

    What is Mongoose, and why do we use it with MongoDB?

    Mongoose is a library that makes it easier to work with MongoDB from a Node.js app. It lets us define a clear "schema" (expected shape) for our data, and gives us simple methods to save, find, update, and delete documents.

    What is a schema in Mongoose?

    A schema describes what fields a document should have, and what type each field should be — like saying "name should be text, and marks should be a number."

    What is the difference between find() and findOne() in MongoDB?

    find() returns every document that matches the search, as a list. findOne() returns only the first matching document it finds, or none at all.

    What is the difference between updateOne() and updateMany()?

    updateOne() updates only the first document that matches a condition. updateMany() updates every single document that matches the condition.

    What is an index in MongoDB, and why does it help?

    An index is like a shortcut list that MongoDB keeps, so it can find matching documents much faster, instead of checking every single document one by one.

    What is the aggregation pipeline in MongoDB?

    The aggregation pipeline lets you process and transform data in multiple connected steps, like filtering, grouping, and then sorting the results, all inside the database itself.

    What is the difference between embedding documents and referencing documents in MongoDB?

    Embedding stores related data directly inside the same document, like putting a student's address right inside their own record. Referencing stores just the _id of a related document instead, similar to a foreign key in SQL, and requires a separate lookup to get the full details.

    What is the purpose of validation in a Mongoose schema?

    Validation rules, like marking a field as required or setting a minlength, stop incorrect or incomplete data from being saved to the database.

    What is the difference between MongoDB Atlas and a local MongoDB installation?

    MongoDB Atlas is a cloud-hosted version of MongoDB, managed by MongoDB itself, so you don't have to install or maintain the database yourself. A local installation runs directly on your own computer.

    What does it mean that MongoDB is "schema-less"?

    It means MongoDB itself does not force every document in a collection to have the exact same fields — two student documents could have slightly different fields. Tools like Mongoose can still add their own structure on top, for safety.

    What is the purpose of populate() in Mongoose?

    populate() automatically replaces a referenced _id with the full document it points to, so you don't have to manually run a second separate query to get the related data.

    What is the difference between deleteOne() and findByIdAndDelete() in Mongoose?

    deleteOne() deletes the first document matching any given condition. findByIdAndDelete() is a shortcut that searches by the document's exact _id and deletes it directly.

    What are MongoDB operators like $gt and $in used for?

    These are special query operators used to build more advanced searches, like $gt meaning "greater than" or $in meaning "matches one of these values in a list."

    Example: { marks: { $gt: 80 } } finds every student with marks greater than 80.
    What is sharding in MongoDB?

    Sharding splits a very large amount of data across multiple servers, so no single server has to store or process all of it alone, helping the database scale for huge amounts of data.

    What is the purpose of a connection string when connecting to MongoDB?

    A connection string is a single line of text containing all the details needed to connect to a database, like its address, username, password, and database name.

    Example: A "Gmail Trigger" starts the workflow when a new email arrives. A "Slack" Action node then sends a notification about that email.
    What is a webhook in n8n?

    A webhook is a special web address (URL) that n8n creates for your workflow. When another app sends data to that URL, it automatically starts the n8n workflow. It is one of the most common ways to trigger a workflow when something happens in an external app.

    Example: Suhani's website sends customer signup details to an n8n webhook URL. n8n receives that data and then saves it to a database automatically.
    What is the difference between n8n Cloud and self-hosted n8n?

    n8n Cloud is the paid, managed version — n8n runs and maintains the server for you, and you just log in and start building. Self-hosted means you install and run n8n on your own computer or server, which gives you full control and is free, but you are responsible for keeping it running.

    How is n8n different from Zapier?

    Both n8n and Zapier connect apps to automate tasks, but n8n is open-source and can be self-hosted for free with no limits on the number of workflows or executions. Zapier is a paid, closed-source service. n8n also lets you write custom code inside nodes, giving developers much more flexibility than Zapier.

    What is an expression in n8n?

    An expression is a small piece of code you can write inside a node's field, using double curly braces, to dynamically use or change data coming from a previous node. It is like a mini template that gets filled in at runtime.

    Example: Inside an email subject field, you write {{ $json.name }} — when n8n runs, it replaces that with the actual name from the incoming data, like "Hello, Vikas!"
    What does $json mean in an n8n expression?

    $json refers to the data (in JSON format) coming from the current item being processed. You use it to access specific fields inside that data.

    Example: If a node receives {"name": "Suhani", "email": "suhani@mail.com"}, you can write {{ $json.email }} in the next node to use Suhani's email address.
    What is a credential in n8n?

    A credential is where you securely save the login details (like an API key, username, or OAuth token) for a service. Once saved, you select that credential inside any node that needs to connect to that service. n8n encrypts and stores credentials safely.

    Example: Vikas saves his Gmail API credentials in n8n once. Every Gmail node in all of his workflows can then use those saved credentials without him typing the password again.
    What is an execution in n8n?

    An execution is one single run of a workflow from the very first node to the last. Every time the workflow is triggered, that counts as one execution. n8n saves a log of each execution so you can see what data went through and whether it succeeded or failed.

    What is an "item" in n8n, and why does it matter?

    An item is one single piece of data moving through the workflow. Most nodes process one item at a time. If a node receives multiple items (like 10 rows from a spreadsheet), it usually processes each one separately, running through the whole workflow chain for each.

    Example: A Google Sheets node reads 5 rows — n8n creates 5 items. The next Email node then sends 5 separate emails, one for each item/row.
    How do you start a workflow automatically on a schedule in n8n?

    You use the Schedule Trigger node as the first node in your workflow. You set how often it should run — like every hour, every day at 9am, or every Monday. n8n then automatically starts the workflow at those times without anyone needing to click anything.

    What is the IF node used for in n8n?

    The IF node checks a condition and splits the workflow into two paths: a "true" path and a "false" path. This lets you make your workflow behave differently depending on the data.

    Example: If the order amount is above ₹1000, go down one path and apply a discount. If the order amount is below ₹1000, go down the other path and keep the normal price.
    What is the Switch node in n8n?

    The Switch node is like an IF node but for more than two choices. You define many different conditions, and the workflow goes down whichever path matches. It is like a multi-option router for your data.

    Example: If the country is "India" go to path 1, if "USA" go to path 2, if "UK" go to path 3, otherwise go to a default path.
    What is the Merge node in n8n?

    The Merge node takes data from two separate branches of a workflow and combines them together into one, so the next node can work with the combined data. It is the opposite of splitting — it brings paths back together.

    What is the Set node used for in n8n?

    The Set node lets you create new fields or change the values of existing fields inside the data as it flows through the workflow. You can also use it to keep only the fields you need and remove the rest.

    Example: The data coming in has 20 fields but the next step only needs "name" and "email". Suhani uses a Set node to keep just those two fields and remove the other 18.
    What is the Code node in n8n?

    The Code node lets you write your own custom JavaScript code to transform or process data in ways that the built-in nodes cannot do on their own. It is useful for complex data changes, calculations, or logic that no ready-made node covers.

    What is the HTTP Request node used for?

    The HTTP Request node lets your workflow call any external API or web address. It can send GET, POST, PUT, DELETE requests to any service that has an API, even if n8n does not have a built-in node for that service. This makes n8n able to connect to almost anything.

    Example: Vikas uses the HTTP Request node to call a weather API every morning and get today's temperature, which is then sent to a Slack channel.
    What is the difference between "Test" mode and "Production" mode in n8n?

    In Test mode, you run the workflow yourself manually inside the n8n editor to check it works correctly. In Production mode, the workflow is activated and runs automatically on its own whenever the trigger fires — real data is processed without you needing to be there.

    What does "active" versus "inactive" mean for a workflow in n8n?

    An active workflow is switched on — it runs automatically whenever its trigger condition happens. An inactive workflow is switched off — it will not run automatically, even if the trigger fires. You can still run it manually by clicking "Execute Workflow" while inactive, but it won't respond to real events.

    What is the "Wait" node in n8n?

    The Wait node pauses the workflow for a set amount of time before continuing to the next node. It is useful when you need a delay between steps — like sending a follow-up email 2 hours after the first one.

    How does error handling work in n8n?

    In n8n you can set up an Error Workflow — a separate workflow that runs automatically whenever another workflow fails. This lets you send yourself a Slack alert or log the failure to a spreadsheet so you know something went wrong and can fix it.

    What is the "Continue on Fail" setting on a node?

    Normally, if a node fails, the whole workflow stops. If you turn on "Continue on Fail" for a specific node, n8n will move on to the next step even if that node had an error, instead of stopping everything. It is useful when a failure on one step should not block the rest of the workflow.

    What is a sub-workflow in n8n?

    A sub-workflow is a separate workflow that can be called and run from inside another workflow, using the "Execute Workflow" node. It is like a reusable function — you build a small workflow once and call it from many other workflows, instead of repeating the same steps everywhere.

    Example: Vikas has a workflow that sends a formatted notification email. Instead of rebuilding those email steps in every workflow, he calls that email workflow as a sub-workflow from 10 other workflows.
    What is the Loop Over Items node used for?

    The Loop Over Items node processes a batch of items one by one (in a loop) rather than all at once. This is useful when you need to do something for each item separately in a controlled way, or when you need to add a delay between processing each item.

    What is the difference between the $json and $node variables in n8n expressions?

    $json gives you the data from the current item in the previous node. $node["NodeName"].json gives you data from a specific named node anywhere earlier in the workflow, not just the one immediately before the current step.

    What is the Filter node in n8n?

    The Filter node checks each incoming item against a condition and only passes through the items that match. Items that do not match the condition are simply removed from the flow.

    Example: Suhani's workflow receives 100 customer records. She uses a Filter node to keep only the customers who are from Mumbai, so only those 30 customers continue to the next step.
    What is the Aggregate node in n8n?

    The Aggregate node combines multiple separate items into one single item (or into a list inside one item). It is useful when you want to process a whole group of records together as one object, instead of one at a time.

    What is the Split In Batches node in n8n?

    If you have a large number of items, the Split In Batches node divides them into smaller groups (batches) and processes each batch separately. This prevents overloading an API with too many requests at once.

    Example: Vikas needs to send API requests for 500 items, but the API only allows 50 requests at a time. Split In Batches sends 50, waits, then sends the next 50, and so on.
    What is the difference between "Run Once for All Items" and "Run Once for Each Item" in a node?

    "Run Once for All Items" means the node runs one single time and receives all the items at once as a group. "Run Once for Each Item" means the node runs separately for every single item one by one. The right choice depends on whether the service or action you're using needs items one at a time or all together.

    What are n8n templates, and why are they useful?

    n8n templates are ready-made workflows built by the n8n team or the community, which you can import with one click and customise for your own needs. Instead of building a workflow from scratch, you start with a working example and just change the details — saving a lot of time.

    How do you pass data between nodes in n8n?

    Data flows automatically from one node to the next through the connection (arrow) between them. Each node passes its output to the next node's input. You access the incoming data inside a node using expressions like {{ $json.fieldName }}.

    What is OAuth authentication in n8n credentials?

    OAuth is a safe way for n8n to connect to services like Google or Slack without you sharing your password. Instead, you click "Connect" in n8n, log into the service in a popup, grant permission, and the service gives n8n a secure token. n8n stores that token as the credential.

    What is the Respond to Webhook node in n8n?

    When an app sends data to an n8n webhook and waits for a response, the Respond to Webhook node is what sends that response back. Without it, the other app would just time out waiting. It lets your workflow receive data, process it, and reply — like a mini API endpoint.

    Can n8n connect to a database directly? Which databases?

    Yes. n8n has built-in nodes for many popular databases including PostgreSQL, MySQL, MongoDB, Redis, and SQLite. You can read, write, update, and delete records directly from your database inside a workflow.

    What is the AI Agent node in n8n?

    The AI Agent node lets you connect an AI language model (like OpenAI's GPT) into your workflow, so it can think, make decisions, use tools you give it, and return intelligent answers. This is used to build AI-powered automations, like a smart customer support bot that can look up orders and reply to customers.

    What is n8n's "Chat Trigger" node used for?

    The Chat Trigger node creates a simple chat interface in n8n's own built-in chat window. It starts the workflow every time a user sends a message in that chat. It is mainly used for building and testing AI chatbot workflows without needing an external chat platform.

    How would Vikas build a simple lead capture workflow in n8n?

    Vikas could use a Webhook Trigger to receive form data when a new lead fills in a website form, then a Google Sheets node to save the lead's name and email into a spreadsheet, then a Gmail node to automatically send the new lead a welcome email — all three steps connected in a chain, running automatically every time someone fills in the form.

    What is the Sticky Note node in n8n?

    A Sticky Note is not a real processing step — it is a yellow note you can add to the canvas to write comments, explanations, or reminders about what a part of the workflow does. It is just for documentation, to make the workflow easier for others (or future-you) to understand.

    What is the difference between n8n's "workflow" and n8n's "execution log"?

    The workflow is the design — the connected nodes you built. The execution log is the record of what actually happened when the workflow ran: what data went through each node, whether it succeeded or failed, and how long it took.

    How does n8n handle large amounts of data — like processing 10,000 rows from a spreadsheet?

    n8n processes items in batches. For very large datasets, you use the Split In Batches node to break the data into smaller chunks (like 100 rows at a time), process each batch, add a small wait if needed to respect API rate limits, and loop until all rows are done.

    Is n8n only for non-developers (no-code users)?

    No — n8n is good for everyone. Non-developers can build automations using the visual drag-and-drop canvas and built-in nodes without writing any code. Developers can also write JavaScript in the Code node, call APIs with the HTTP Request node, and build complex custom logic. n8n describes itself as "low-code" — visual first, but with the power to go deeper.

    What is the purpose of the "n8n Form Trigger" node?

    The n8n Form Trigger creates a real web form that n8n hosts for you. When someone fills it in and clicks Submit, the workflow starts with the form data as the input. It is a quick way to build a form-triggered workflow without needing an external form tool.

    Example: Suhani creates a feedback form using the n8n Form Trigger. Every time someone submits feedback, n8n saves it to a Google Sheet automatically — no separate form tool like Typeform is needed.
    What does "pinning data" mean in n8n?

    Pinning data means saving a snapshot of the data that came out of a node during a test run. While you are building and editing later nodes, n8n uses the pinned data instead of running the first node again. This saves time — you don't need to re-trigger the workflow every time you want to test a later step.

    What happens when a workflow fails mid-execution in n8n?

    When a node fails, n8n stops executing the workflow at that point and marks the execution as failed in the execution log. You can view exactly which node failed, what error occurred, and what data was being processed at that moment. If you have an Error Workflow set up, that separate workflow will also run to notify you.

    How do environment variables work in n8n?

    Environment variables let you store configuration values — like API URLs or secret keys — outside your workflows, in the server settings. Inside a workflow you can access them using $env.VARIABLE_NAME. This is useful for values that change between development and production, without having to edit every workflow.

    What is the difference between the "Webhook" trigger and the "HTTP Request" node?

    The Webhook trigger is passive — it waits and listens for another app to call it. The HTTP Request node is active — it goes out and calls another app's URL. One receives data, the other sends a request to get or send data somewhere else.

    Can you version control n8n workflows? How?

    Yes. n8n workflows can be exported as JSON files, which can then be saved in Git (like GitHub) just like normal code files. This lets a team track changes, review who changed what, and restore older versions of a workflow. n8n also has built-in workflow versioning on n8n Cloud.

    What is the n8n community, and where can you find help?

    n8n has an active community forum at community.n8n.io where you can ask questions, share workflows, and find solutions. There are also thousands of ready-made templates on n8n.io/workflows, and the full official documentation is at docs.n8n.io.

HTML builds the structure. CSS makes it look nice. JavaScript makes it work and react to the user.

Hoisting moves declarations to the top of their scope before the code runs.
Event delegation means putting one listener on a parent, instead of many listeners on each child.
