HyperText Markup Language — Structure of the Web

What is HTML?

HTML stands for HyperText Markup Language. It is the standard language used to create the structure of web pages. Think of it as the skeleton of a website — CSS is the skin, and JavaScript is the muscles.

Key Insight
HTML is NOT a programming language. It is a markup language — it tells the browser how to display content using tags.

The Box Model

Every HTML element is a rectangular box. The box model describes the spacing around it.

/* Box model layers (outside in): margin > border > padding > content */
.box {
  width: 200px;          /* content width */
  padding: 20px;        /* space inside border */
  border: 2px solid black; /* border */
  margin: 10px;         /* space outside border */
  box-sizing: border-box; /* IMPORTANT: width includes padding+border */
}
Common Mistake
Always add box-sizing: border-box globally. Without it, padding and border ADD to the declared width, causing layout bugs.

Flexbox

Flexbox is used to align items in ONE direction (row or column). Think of it as a "flex container" that controls how its children line up.

🧩 Flexbox Quick Reference
.container {
  display: flex;

  /* Direction */
  flex-direction: row | row-reverse | column | column-reverse;

  /* Alignment on MAIN axis (horizontal if row) */
  justify-content: flex-start | flex-end | center | space-between | space-around | space-evenly;

  /* Alignment on CROSS axis (vertical if row) */
  align-items: stretch | flex-start | flex-end | center | baseline;

  /* Wrapping */
  flex-wrap: nowrap | wrap | wrap-reverse;

  /* Gap between items */
  gap: 16px;
}

.item {
  flex: 1;          /* grow, shrink, basis shorthand */
  align-self: center; /* override align-items for one item */
  order: 2;         /* change visual order */
}
JA = Justify → main Axis, Align → cross Axis

Hoisting — Step by Step

JavaScript moves (hoists) declarations to the top of their scope before executing code. Only declarations are hoisted, NOT initializations.

// What you write:
console.log(name);    // undefined (NOT error)
var name = "Rahul";

// What JS sees (after hoisting):
var name;             // declaration moved to top
console.log(name);    // undefined
name = "Rahul";       // assignment stays

// Functions are fully hoisted:
greet();               // Works! Outputs "Hello"
function greet() { console.log("Hello"); }

// Arrow functions are NOT hoisted:
greet2();              // ❌ TypeError
const greet2 = () => console.log("Hi");

Closures

A closure is when a function "remembers" variables from its outer scope, even after the outer function has finished executing.

function makeCounter() {
  let count = 0;             // This variable is "closed over"
  return function() {
    count++;                  // Inner fn remembers 'count'
    return count;
  };
}

const counter = makeCounter();
console.log(counter());    // 1
console.log(counter());    // 2
console.log(counter());    // 3  (count persists!)
Real-world use of Closures
Closures are used in: debouncing, throttling, event handlers, module patterns, memoization, and private variables.

Array Methods (ES6+)

const nums = [1, 2, 3, 4, 5];

// map — transform each element, returns new array
nums.map(n => n * 2);              // [2, 4, 6, 8, 10]

// filter — keep elements matching condition
nums.filter(n => n > 2);           // [3, 4, 5]

// reduce — combine all to single value
nums.reduce((acc, n) => acc + n, 0); // 15 (sum)

// find — first element matching condition
nums.find(n => n > 3);             // 4

// some — true if ANY element matches
nums.some(n => n > 4);             // true

// every — true if ALL elements match
nums.every(n => n > 0);            // true

// flat — flatten nested arrays
[1, [2, 3], [4]].flat();           // [1, 2, 3, 4]

// includes — check if value exists
nums.includes(3);                  // true

Debouncing & Throttling

// DEBOUNCE — wait until user stops, then fire once
// Use case: search input (don't call API on every keystroke)
function debounce(fn, delay) {
  let timer;
  return function(...args) {
    clearTimeout(timer);                       // reset timer each call
    timer = setTimeout(() => fn(...args), delay); // fire after delay
  };
}

// THROTTLE — fire at most once per interval
// Use case: scroll handler, window resize
function throttle(fn, interval) {
  let lastCall = 0;
  return function(...args) {
    const now = Date.now();
    if (now - lastCall >= interval) {
      lastCall = now;
      fn(...args);
    }
  };
}

Execution Context & Call Stack

When JavaScript runs, it creates an Execution Context. The Call Stack is a data structure that tracks function calls — last in, first out (LIFO).

// DRY RUN — trace the call stack:
function c() { return 1; }
function b() { return c(); }
function a() { return b(); }
a();

// Call Stack (bottom to top):
// [Global]
// [Global] → a()
// [Global] → a() → b()
// [Global] → a() → b() → c()
// c returns 1 → b returns 1 → a returns 1

The Most Popular UI Library

What is React?

React is a JavaScript library for building user interfaces. It was created by Facebook/Meta. React breaks your UI into small reusable pieces called components.

Think of a webpage like a LEGO set — React gives you individual LEGO bricks (components) that you assemble into a full page.

JSX — JavaScript + HTML

// JSX looks like HTML but it's actually JavaScript
function Greeting() {
  const name = 'Rahul';
  return (
    <div className="card">           {/* className, not class */}
      <h1>Hello, {name}!</h1>         {/* JS in {} */}
      <p style={{color: 'red'}}>Hi</p>  {/* double {{}}: outer=JS, inner=object */}
    </div>
  );
}

useState — The State Hook

State is data that can change over time. When state changes, React re-renders the component automatically.

import { useState } from 'react';

function Counter() {
  // [currentValue, functionToUpdate] = useState(initialValue)
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>+</button>
      <button onClick={() => setCount(prev => prev - 1)}>-</button>
      {/* Using function form (recommended for prev state) */}
    </div>
  );
}

useEffect — Side Effects

useEffect runs code AFTER the component renders. Use it for API calls, timers, subscriptions, DOM manipulation.

import { useEffect, useState } from 'react';

function UserList() {
  const [users, setUsers] = useState([]);

  // Runs ONCE after first render (empty dependency array [])
  useEffect(() => {
    fetch('https://jsonplaceholder.typicode.com/users')
      .then(res => res.json())
      .then(data => setUsers(data));

    // Cleanup function (runs when component unmounts)
    return () => console.log('Component unmounted');
  }, []);  // [] = run once. [id] = run when id changes. nothing = run every render

  return <ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>;
}

useRef — Reference to DOM

import { useRef } from 'react';

function FocusInput() {
  const inputRef = useRef(null);

  // useRef does NOT cause re-render when changed
  const handleFocus = () => {
    inputRef.current.focus();  // Directly access DOM element
  };

  return (
    <div>
      <input ref={inputRef} type="text" />
      <button onClick={handleFocus}>Focus Input</button>
    </div>
  );
}

useMemo & useCallback

useMemo — Cache computed values
const expensiveValue = useMemo(() => {
  return heavyCalculation(data);
}, [data]);
// Re-computes only when 'data' changes
useCallback — Cache function
const handleClick = useCallback(() => {
  doSomething(id);
}, [id]);
// Same function reference until 'id' changes
useMemo = caches a VALUE. useCallback = caches a FUNCTION

Context API — Avoid Prop Drilling

Prop drilling = passing props down many levels through components that don't need them. Context solves this.

import { createContext, useContext, useState } from 'react';

// 1. Create context
const ThemeContext = createContext(null);

// 2. Provide context (wrap your app/section)
function App() {
  const [theme, setTheme] = useState('light');
  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      <Navbar />
      <Main />
    </ThemeContext.Provider>
  );
}

// 3. Consume anywhere in tree (no prop drilling!)
function Navbar() {
  const { theme, setTheme } = useContext(ThemeContext);
  return <nav className={theme}>...</nav>;
}

Virtual DOM & Reconciliation

🔄 How React Renders
  1. State/props change → React creates a new Virtual DOM (lightweight JS copy of real DOM)
  2. React compares new Virtual DOM with previous one (this is diffing/reconciliation)
  3. React finds the minimum changes needed
  4. Only those changes are applied to the real DOM
Why Virtual DOM?
Real DOM manipulation is slow. Virtual DOM makes updates efficient by batching and minimizing actual DOM changes.

Custom Hooks

// Custom hooks always start with "use"
function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    fetch(url)
      .then(r => r.json())
      .then(d => { setData(d); setLoading(false); })
      .catch(e => { setError(e); setLoading(false); });
  }, [url]);

  return { data, loading, error };
}

// Usage — reuse in any component!
function Posts() {
  const { data, loading } = useFetch('https://api.example.com/posts');
  if (loading) return <p>Loading...</p>;
  return <div>{data?.map(p => <p key={p.id}>{p.title}</p>)}</div>;
}

React Performance Optimization

  • React.memo — Prevents re-render if props haven't changed
  • useMemo — Cache expensive calculations
  • useCallback — Stable function references (for memo'd children)
  • Lazy Loading + Code Splitting — Load components only when needed
  • Key prop in lists — Helps React efficiently update lists
  • Avoid anonymous functions in JSX — They create new references each render

⚡ Quick One-Liners for Interview

HTML is a markup language. CSS is a stylesheet language. JavaScript is a programming language.
Semantic HTML uses meaningful tags like <header>, <main>, <article> that describe content purpose.
CSS specificity order: Inline > ID > Class > Tag. Use IACS to remember.
Flexbox = 1D layout (row or column). Grid = 2D layout (rows AND columns).
Closure = inner function accessing outer function's variables after outer function returns.
Hoisting = JS moves var declarations and function declarations to top of scope before execution.
Event delegation = one listener on parent instead of many on children, using e.target to identify source.
Debounce = wait until user stops triggering event. Throttle = execute at most once per interval.
Promise has 3 states: pending → fulfilled or rejected. async/await is syntactic sugar over promises.
React's Virtual DOM diffs new and old trees (reconciliation) and only updates changed parts of real DOM.
useState = reactive data. useEffect = side effects. useRef = DOM reference without re-render.
useMemo = cached value. useCallback = cached function. Both use dependency arrays.
Bootstrap uses 12-column grid. Tailwind uses utility classes. React is a UI component library.
